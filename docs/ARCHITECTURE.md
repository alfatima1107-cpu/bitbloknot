# Как устроен БитБлокнот — объяснение простым языком

Этот файл — для автора проекта. Прочитай его, и ты сможешь объяснить жюри, как работает каждая часть.

## 1. Общая картина

БитБлокнот — это **веб-сайт, который работает на твоём ноутбуке**. Интернет ему не нужен.

```
 Браузер (Chrome, Edge)          Программа на Python (app.py)          Файлы
 ┌──────────────────┐  запрос   ┌──────────────────────────┐  читает  ┌──────────────┐
 │ страница урока,  │ ────────► │ Flask: какой адрес —     │ ───────► │ content/*.json│
 │ тренажёр, тест   │ ◄──────── │ такую страницу собрать   │ ◄─────── │ data/*.db     │
 └──────────────────┘   HTML    └──────────────────────────┘ пишет    └──────────────┘
```

1. Ты открываешь адрес, например `/topic/8` (тема 8).
2. Браузер отправляет **запрос** программе на Python.
3. Программа (библиотека **Flask**) понимает, какая страница нужна, берёт текст урока из `content/08_image.json`,
   твой прогресс из базы данных и **собирает HTML-страницу** по шаблону из `templates/`.
4. Браузер показывает страницу. Тренажёры «оживают» благодаря **JavaScript**.

Такая схема называется **клиент — сервер**: браузер — клиент, программа на Python — сервер.
Только здесь они оба живут на одном компьютере (адрес `127.0.0.1` означает «этот компьютер»).

## 3. База данных

Прогресс хранится в файле `data/bitbloknot.db` — это база **SQLite** (она встроена в Python).
В базе несколько **таблиц**, как листы в Excel:

- `users` — ученики (имя, аватар);
- `steps_done` — какие шаги уроков пройдены;
- `attempts` — каждая решённая задача: верно или нет, **тип ошибки**, уровень;
- `tests` — результаты тестов;
- `topic_state` — уровень сложности и дата следующего повторения по каждой теме.

## 4. Генератор задач — откуда берутся бесконечные задачи

Задачи не хранятся готовыми — их **придумывает программа**. Пример для темы «Изображения» (`tutor/generators/image.py`):

1. Случайно выбрать размер рисунка (например, 16 × 32) и число цветов (например, 4).
2. Посчитать ответ по формуле: глубина цвета i = 2 бита, объём = 16 × 32 × 2 = 1024 бита.
3. Составить текст задачи и **пошаговое решение**.
4. Посчитать **ответы-ловушки**: что получит ученик, если ошибётся типичным образом.
   Например, если он умножит на число цветов (4) вместо бит (2), получится 2048 — это ошибка «перепутал N и i».

Сложность зависит от уровня: на лёгком — маленькие числа и степени двойки, на сложном — перевод в Кбайты
и обратные задачи («найди число цветов по объёму»).

## 5. Как репетитор понимает, в чём ошибка

Это главная «фишка» проекта — **интеллект без ИИ**.

```
ответ ученика ──► совпал с правильным? ── да ──► «Верно!»
                        │ нет
                        ▼
              совпал с ловушкой? ── да ──► точная подсказка: «Похоже, ты перепутал биты и байты»
                        │ нет
                        ▼
                  общая подсказка
```

Первая ошибка — подсказка и вторая попытка. Вторая ошибка — полное решение по шагам и новая похожая задача.
Каждая ошибка с её типом записывается в базу, и потом блок «Сегодня» может сказать:
«Недавно ты 3 раза путал биты и байты».

## 6. Правила «умного репетитора» (`tutor/adaptive.py`)

1. **Уровни сложности.** 3 верных ответа подряд — уровень выше; 2 ошибки подряд — ниже. Уровней три.
2. **Процент освоения темы:** шаги урока 20 % + тренажёр 10 % + точность последних 10 задач 30 % + лучший тест 40 %.
3. **Интервальное повторение.** Сданную тему сайт предлагает повторить через 1, потом 3, потом 7 дней.
   Это научный приём: так информация переходит в долговременную память.
4. **Блок «Сегодня»** выбирает совет по приоритету:
   недоконченный урок → тест хуже 70 % → подошёл срок повторения → следующая тема по программе
   (с учётом того, какие темы нужно знать заранее).

## 7. Тренажёры

Тренажёры — это JavaScript прямо на странице (`templates/trainers/`). Например, «Звукозапись»:
- рисует звуковую волну на `<canvas>`;
- делает «замеры» с выбранной частотой и округляет их до 2ⁱ уровней — получаются «ступеньки»;
- через **Web Audio API** браузера синтезирует звук: сначала оригинал, потом оцифрованную версию.
  Разницу слышно ушами — так понятнее, зачем нужна высокая частота дискретизации.

Когда ученик выполняет задание тренажёра, JavaScript сообщает серверу (`/api/trainer/8/done`),
и это засчитывается в освоение темы.

## 8. Как мы проверяем, что всё правильно

**Автотесты** (`tests/`, запуск `pytest`) — программа, которая проверяет программу:
- генерирует **тысячи** случайных задач и проверяет, что правильный ответ принимается, а ловушки распознаются;
- проверяет известные значения (3 Кбайт = 24 576 бит, 33 буквы → 6 бит);
- проверяет правила репетитора (уровни, повторения, оценки);
- проверяет все 12 уроков: в каждом 5–7 шагов, у вопросов есть правильные ответы, в банке теста не меньше 20 вопросов;
- открывает все страницы сайта.

Все вопросы курса собраны в `docs/QUESTIONS.md`, чтобы их мог проверить взрослый или учитель.

## 9. Вход и безопасность (`tutor/auth.py`)

- Каждый ученик регистрируется сам: уникальный **логин** и **PIN из 4 цифр**.
- **PIN не хранится в базе.** Хранится его **хеш** — результат необратимой функции (библиотека `werkzeug.security`).
  При входе программа считает хеш введённого PIN и сравнивает с сохранённым. Даже если кто-то скопирует файл базы,
  PIN оттуда не узнать.
- **Защита от подбора.** У PIN из 4 цифр всего 10 000 вариантов. После 5 неверных попыток подряд вход по этому
  логину блокируется на 30 секунд. Перебрать все варианты займёт больше 16 часов.
- Если логин неверный, сайт не говорит «такого логина нет», а пишет «Неверный логин или PIN» — так нельзя узнать,
  какие логины существуют.
- Сайт работает без интернета, поэтому «восстановить пароль по почте» нельзя. Вместо этого сразу после регистрации
  открывается карточка «Сфотографируй меня!» с логином и PIN.

## 10. Кабинет, серия и достижения

- **Серия дней** (`adaptive.streak_from_days`) — сколько дней подряд ученик занимался. Один пропущенный день
  в любые 7 дней прощается; два пропуска подряд или два за неделю — серия сгорает. Рекорд хранится.
- **Достижения** (`tutor/achievements.py`) — 14 значков. Каждое правило — простая проверка по базе
  (например, «10 задач подряд с первой попытки»). После каждого действия ученика программа проверяет правила
  и показывает всплывающее сообщение о новом значке.

## 11. Вопросы, которые может задать жюри

**— Почему Python и Flask?** Python — понятный язык, его изучают в школе. Flask — простая библиотека для сайтов на Python.

**— Где хранятся данные?** В базе SQLite на компьютере. Интернет не нужен, личные данные никуда не отправляются.

**— Как защищены пароли?** PIN хранится только в виде хеша, а после 5 неверных попыток вход замирает на 30 секунд.

**— Есть ли тут искусственный интеллект?** Пока нет: «умность» — это правила, которые можно объяснить
(уровни, ловушки, повторение). ИИ-чат (GigaChat или YandexGPT) — следующий этап, для него уже есть заготовка `tutor/assistant.py`.

**— Чем вы отличаетесь от сайтов с тестами?** Задачи бесконечные и генерируются заново; репетитор понимает,
*какую именно* ошибку ты сделал; есть интерактивные тренажёры и повторение по научной методике.

**— Как проверяли, что ответы правильные?** Автотесты на тысячах случайных задач + файл со всеми вопросами для проверки.

**— Кто писал код?** Проект сделан методом вайб-кодинга: я был автором идеи, архитектором и тестировщиком —
придумал продукт, принимал решения и проверял результат, а код писал ИИ-ассистент по моим заданиям.
История решений — в `docs/DEVLOG.md`.
